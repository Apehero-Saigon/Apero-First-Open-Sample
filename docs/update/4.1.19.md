# Integration Guide — v4.1.19

> **Upgrade target:** v4.1.18 → v4.1.19

---

## 1. Pick a flow: D0 or D7

Extend exactly **one** of the two abstract activities.

|                 | **D0 (`AstronexFirstOpenActivity`)** | **D7 (`AstronexD7FirstOpenActivity`)** |
|-----------------|--------------------------------------|----------------------------------------|
| Welcome screen  | Yes                                  | No                                     |
| Required config | `FOD0AdsConfig`                      | `FOD7AdsConfig`                        |

> Ask the requester (PO) which flow to use. If no information is provided, default to **D0** for apps that monetize with ads.

---

## 2. Implement your `FirstOpenActivity`

Override `setUpAdConfig()` and return the config that matches your flow. Every ad-ID is a **required** constructor parameter — pass `null` explicitly when you don't have an ID for that slot.

        nativeLanguageDupId = BuildConfig.native_language_dup,
        nativeWelcomeHighId = BuildConfig.native_welcome_high,
        nativeWelcomeId = BuildConfig.native_welcome,

## 3. App Open Resume (optional)

Handles `native_resume` combined with `open_resume` driven by the PO's requirement. The branch (native vs. open) and the cap/cooldown values come from remote config, so this initializer must be called from `FOCallback.onRemoteConfigResult` (see §4) once the values are available.

### Instructions

- Collect every `Activity` class that should show the resume ad into `listActivities`.
- Read the PO-defined remote config flag (e.g. `useNativeResume`) plus cap and cooldown values.
- If the flag is on, call `AppOpenResumeManager.setUpNativeResume(...)` with a `NativeAdGroup` + `NativeResumeConfig`.
- Otherwise, call `AppOpenResumeManager.setUpOpenResume(...)` with an `AppOpenAdGroup`.
- Apply the remote-config ad IDs via `.apply { config(...) }` on the ad group.

### Sample code

```kotlin
fun initAstronexAdResume(
    // Your params get from remote config. Check PO's requirement
    // It should be called on onRemoteConfigResult(remoteConfigRepository: RemoteConfigRepository) {}
) {
    val listActivities = mutableListOf<KClass<out Activity>>()
    listActivities.add(/* your activities */)

    if (useNativeResume) { // Check PO's requirement for this condition
        AppOpenResumeManager.setUpNativeResume(
            adGroup = NativeAdGroup(
                BuildConfig.native_resume_high to "native_resume_high",
                BuildConfig.native_resume to "native_resume",
                name = "native_resume",
                reloadAfterVideo = false,
                isFullScreen = true,
            ).apply { config(/* remote config: native_resume_high, native_resume here */) },
            config = NativeResumeConfig(
                limitCapResumeAd = /* Enter limit */,
                cooldownResumeAd = /* Enter cooldown */,
            ),
            activities = listActivities.toTypedArray(),
        )
    } else {
        AppOpenResumeManager.setUpOpenResume(
            adGroup = AppOpenAdGroup(
                BuildConfig.open_resume to "open_resume",
                name = "open_resume",
            ).apply {
                config(/* remote config: open_resume here */)
            },
            activities = listActivities.toTypedArray(),
        )
    }
}
```

## 4. Read Firebase Remote Config — `FOCallback.onRemoteConfigResult` (optional)

```kotlin
import com.astronex.firstopen.app.FOCallback
import com.astronex.firstopen.data.repository.RemoteConfigRepository

val callback = object : FOCallback() {
    override suspend fun onRemoteConfigResult(remoteConfigRepository: RemoteConfigRepository) {
        val flag  = remoteConfigRepository.getBooleanConfig("my_flag", false)
        val text  = remoteConfigRepository.getStringConfig("my_text", "")
        val count = remoteConfigRepository.getIntConfig("my_count", 0)
        val price = remoteConfigRepository.getLongConfig("my_price", 0L)
        val ratio = remoteConfigRepository.getFloatConfig("my_ratio", 0f)
    }
}
```

Wire it via `.setCallback(callback)` inside `onSetupFOConfig()` (see §2.1 / §2.2).
